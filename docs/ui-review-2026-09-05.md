# UI review — September 5, 2026

Built on the existing uncommitted UI redesign. The review preserved its theme, typography, provider colors, document layout, and execution features.

## Improvements and fixes

- Planning starts with the question or goal, followed by optional project context. Three example prompts help with an empty form, and a keyboard-shortcut hint explains how to submit.
- Closing the composer with Escape or the close button preserves its draft, required conditions, and expanded controls. A successful submission clears the draft. Drafts are retained in memory, not across a page reload.
- Creation errors appear and receive focus inside the composer. Invalid paths get readable guidance. Connection failures preserve the draft, and a pending-state guard prevents repeated clicks or keyboard shortcuts from creating duplicate requests.
- Run projections merge by recorded event sequence. A delayed HTTP reply cannot overwrite newer live progress. Background updates preserve the ordering of history entries, while same-sequence adviser updates remain supported.
- Historical revisions display their own review status and condition assessments. They cannot inherit the current document’s readiness. A notice and a “Back to latest” button identify older versions. Export labels explicitly identify the latest document, which is what the existing export endpoint saves.
- Completed workflow history is collapsed, and completed-run provider details move into Run details. Mobile history expands on demand and collapses after selection, giving the answer more room.
- Paused or stopped work has no misleading activity spinner or loading skeleton. A cancelled run without a document says “No document produced” and “Not reviewed.”
- Keyboard focus moves to the goal on opening the composer, returns to the opener when dismissing it, and moves to a newly created or selected run. Dialog visibility and focus changes occur before paint. Skip to content leaves the session URL intact.
- The onboarding privacy text now explains that history is local while selected evidence is sent to Codex and Claude.

## Verification

The following checks passed on the final implementation:

| Check | Result |
| --- | --- |
| `npm run build` | TypeScript and production Vite build passed |
| `npm run verify:ui-regressions` | All new regression cases passed |
| `npm run verify:planning-ui` | Clarification, revision, export, restart, and document checks passed |
| `npm run test -w @collab/ui` | Existing execution, adviser, keyboard, reflow, and accessibility checks passed |
| `git diff --check` | No whitespace errors |

The new regression suite checks 320, 390, 768, and 1280-pixel layouts in light and dark themes. Maximum horizontal overflow was **0 pixels**, with **0 serious or critical axe violations**. The existing accessibility suite also passed its 200% zoom reflow check.

Computer use in the Codex in-app browser verified example prompts, invalid-path recovery, Escape and reopening with a preserved draft, keyboard submission, clarification and resumption, historical revision feedback, mobile history navigation, cancellation, light/dark layouts, and Markdown export. The exported fixture document was confirmed on disk.

All verification used isolated deterministic fixtures and started **zero models**. It verifies UI behavior, not live provider quality, authentication, or billing availability. The preview uses temporary state and is separate from the normal application state.
